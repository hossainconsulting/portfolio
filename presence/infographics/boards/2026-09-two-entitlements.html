Two different things are both called “entitlement”.

Conflating them is the classic error in a warranty data model. One is a commercial promise. The other is a clock.

01 · CUSTOM OBJECT

Warranty_Entitlement__c

The commercial warranty on an appliance.

  • Plan tier, coverage window, claim limit, retailer
  • Answers “is this dishwasher covered?”
  • Read by the agent’s coverage action
  • Never generated by the model
02 · STANDARD OBJECT

Entitlement + Process + Milestones

The service level. How fast we must respond.

  • First Response 48h / 24h / 8h across three tiers
  • Answers “what is the deadline?”
  • Runs the SLA clock on the case
  • Escalates when a milestone is missed
THE RULE

The coverage check reads the custom object. The SLA clock runs on the standard one. Keep them separate. Name them differently in every document, every field label and every conversation with the client.

If one object does both jobs, a warranty expiry will silently stop an SLA clock, or a missed milestone will look like lost cover. I have seen both, and the fix is always the data model, never the agent.
